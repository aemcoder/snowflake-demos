## Issue deep-dives

### MAJOR-1 — Section first-class CSS collision (glossier `ugc-grid`)

**Symptom:** The UGC grid section collapses to 29% width (tiles 113px vs 389px).

**Root cause:** Same pattern as Heathrow's `phases` → `phased-expansion` rename.
The agent chose `ugc-grid` as the section first-class (from the section's inner
div class), but `.ugc-grid { display: grid; grid-template-columns: ... }` already
exists in the page CSS and fires on the outer `<section>` element when it carries
that class — collapsing the layout.

**Fix:** Rename section first-class to `ugc` (or `ugc-campaign`, any name that
doesn't appear as a CSS selector). The original `ugc-grid` stays in the class
list; the CSS rule still applies to the inner `div.ugc-grid` where it belongs.

**Learning:** The discriminator-hierarchy rule (learnings.md 2026-05-19) says
"verify the chosen slug doesn't appear elsewhere in the section's CSS scope."
This confirms that rule. Should be promoted to the methodology.

### MAJOR-2 — CSS `--ground` wrong value (oatly)

**Symptom:** Whole page renders on cold white (#FFFFFF) instead of warm cream
(#F5F0E8). Hero content overlaps sticky nav. Bottom taskbar missing at 800px.

**Root cause unclear** — CSS file passes the health check (starts with `:root`),
so the extraction was correct. Possible causes:
1. The CSS `:root { --ground: #F5F0E8 }` declaration is present but overridden
   later in the stylesheet (check for duplicate `:root` block or another
   `--ground` value further down).
2. The page CSS was extracted from the wrong line range (oatly has a complex
   inline style with multiple `:root` override blocks for different contexts).

**Fix:** Inspect `styles/oatly-a.css` on the branch. Find all `--ground`
declarations. The last one wins; fix it to be `#F5F0E8`.

### MAJOR-3 — Lenis CDN dependency fails (jfk-airport)

**Symptom:** Task-panel section renders as empty dark navy block. Scroll-reveal
sections hidden. CDN `https://cdn.jsdelivr.net/...` returns HTML (404) instead
of JS.

**Root cause:** The jfk-airport source has animation JavaScript that loads Lenis
from jsdelivr CDN. The page's animations engine (`scripts/jfk-airport-a-animations.js`)
references Lenis. The CDN is either blocking, throttling, or temporarily down.

**Fix options:**
1. Vendor Lenis: download `lenis.min.js` + `lenis.min.css`, commit to the repo,
   update the animations script to reference the local paths.
2. Switch CDN to unpkg.com or a more reliable alternative.
3. Remove Lenis dependency — if the only use is smooth scrolling, replace with
   native `scroll-behavior: smooth` in CSS and remove the JS.

**Recommended:** Option 1 (vendor). This is also required for any future
offline/self-hosted demos.

### MAJOR-4 — Images blocked by source CDN (onemedical)

**Symptom:** 10/11 images `about:error`. All sourced from
`www.onemedical.com/media/images/...`.

**Root cause:** The onemedical.com CDN blocks external requests (hotlink
protection). When the AEM Media Bus fetches the absolute image URLs from the DA
cells, the CDN returns 403/404. The pipeline renders `about:error`.

**Fix:** Download all 10 images from the source URL, commit to the repo under
`assets/onemedical/`, update the DA cells to use absolute branch URLs
(`https://sd-onemedical-a--snowflake-demos--aemcoder.aem.live/assets/...`),
re-PUT the DA doc, re-preview.

**Generic learning:** If a source page uses images from a corporate CDN (any
brand's own `cdn.brand.com`), expect hotlink protection. Always verify images
during the Analyze phase by checking if the image URLs respond to HEAD requests
from the public internet. If they 403, plan to vendor.

### MAJOR-5 — Lifestyle-grid images 1/3 size (lovesac)

**Symptom:** `.lifestyle-grid` card images render 136×170px instead of 393×491px.
Section height 635px vs 838px. The section appears collapsed/squashed.

**Root cause:** Likely a CSS width/height rule on the image or its container that
doesn't match the source's sizing. The EDS `<img>` slot writer replaces `src`/`alt`
but preserves the parent's CSS. If the parent container has a fixed width/height
that's too small, the image renders small.

**Fix:** Inspect the rendered `.lifestyle-grid .lg-item` in the production DOM.
Compare CSS `width`/`height`/`aspect-ratio` against source. The most likely
cause is that the image slot was placed on an `<img>` inside a container
`<div>` that has a constrained size — check if `max-width: 100%` is missing or
if a CSS variable controlling grid column sizes doesn't resolve.

Also: 4 empty heading elements (`<h1>`, `<h2>×3`) are in the DOM with no content.
These are `[data-slot]` elements that received no authored value. Fix: either supply
the DA content, or remove the `data-slot` from static headings in the template if
they're design-only and not supposed to be authored.

## Polestar-specific: footer nav invisible (found and fixed)

**What happened:** Review agent reported polestar ✓ MINOR, no fix needed. User caught that footer nav was actually missing. Two nested bugs:

1. Page CSS `.footer { display: grid; grid-template-columns: repeat(5,1fr) }` also fired on the EDS block wrapper `<div class="footer block">` (class `footer` picked it up). Wrapper had only 1 child → inner content collapsed to 20% width. Fixed by changing to `footer[data-section="footer"]>.footer { ... }`.

2. Substrate CSS `footer > .footer { visibility: hidden }` also fired on the fragment's `<div class="footer">` (direct child of `<footer data-section="footer">`, which is a `<footer>` element). That div has no `data-block-status` attribute → never made visible. Fixed by adding `visibility: visible` to the scoped rule.

**Root cause pattern:** When a page CSS class name (e.g. `.footer`) coincides with the EDS block name, layout rules leak into the EDS block wrapper. AND when a fragment uses `<footer>` as its root element (nested inside the EDS `<footer>` landmark), the substrate's `footer > .footer { visibility: hidden }` leaks into the fragment's inner divs.

**Substrate fix needed:** Change `footer > .footer { visibility: hidden }` to `footer > .footer.block { visibility: hidden }` — the `.block` qualifier would limit it to EDS block wrappers only. This is a substrate-level improvement that would prevent this class of bug.

## Cross-run learnings to promote

1. **Corporate CDN hotlink protection is a blocker.** If source images come from
   `brand.com/media/...` (not a public CDN), verify with a HEAD request during
   Analyze phase. If they 403, vendor the images before generating the DA doc.
   Affects: onemedical, ups-gb.

2. **Check `--ground` (and other root vars) AFTER CSS extraction.** A page with
   multiple `:root` blocks (context-specific overrides) can extract incorrectly.
   Run `grep -c ':root' styles/<template>.css` — if > 1, verify the last `--ground`
   is the intended base value.
   Affects: oatly.

3. **CDN dependencies in animations scripts must be verified.** If the source
   references CDN motion libs (Lenis, GSAP, etc.), validate the CDN URL returns
   valid JS before shipping. If it's unreliable, vendor the lib.
   Affects: jfk-airport.

4. **CSS class collision detection needs to be systematic.** The Analyze phase
   should grep the CSS for every candidate first-class before assigning it, not
   just eyebrow slugs. Any class that appears as a CSS selector targeting layout
   properties (display, grid, flex, width, height) must be avoided.
   Affects: glossier (new), heathrow-phases (run 001 learnings).

5. **Page CSS block-name classes leak into EDS block wrappers.** If page CSS has `.{blockname} { ... }` layout rules (display, grid, visibility, etc.), those fire on the EDS block wrapper `<div class="{blockname} block">` too. Always scope such rules with a semantic parent selector (e.g. `footer[data-section]>.footer`) or add `visibility: visible` to counteract inherited substrate rules.
   Affects: polestar (`footer`), glossier (partial — `ugc-grid`).

6. **Substrate `footer > .footer { visibility: hidden }` fires on ANY `.footer` div that is a direct child of ANY `<footer>` element** — including fragment content. The substrate intended this for the EDS block wrapper only. The fix is to qualify as `footer > .footer.block` in the substrate, or add `visibility: visible` in the page CSS for the fragment's inner divs.
   Affects: polestar.

7. **JS-loaded / lazy-loaded images aren't captured by curl.** During capture,
   playwright-cli only captures images visible at initial render. Images loaded
   via IntersectionObserver or JS carousel rotation won't appear in the source
   HTML. These result in empty DA image slots.
   Affects: festool.
